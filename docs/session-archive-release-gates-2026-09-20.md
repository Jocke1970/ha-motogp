# Session archive — release gates and data-file placement

Date: 2026-09-20. Branch: `dev`. Status: **release candidate pending host verification, not deployed**.

## Two file types: never rename one into the other

- **Captured race / replay observation**: `motogp-lap-observations-YYYYMMDD-HHMMSS-PID.jsonl`. This is the earlier standalone Recorder capture (44 snapshots, 596 observed completed laps in the analyzed example). It is a newline-delimited *observation log*. Its original path was `/config/motogp-lap-observations-20260920-133105-1371415.jsonl`. Keeping a copy in a dedicated replay/input folder is fine; leaving it at its original location is also fine. It is NOT automatically loaded by the integration and must NOT be renamed `.json` or substituted for an archive file.
- **Persistent automatic session archive**: generated by the new archive engine on approved, TV-delayed and session-identified snapshots, underneath `/config/motogp_data/<season>/<event>/` in `.json` schema version 1. The engine derives a safe unique filename from official season/event/class/session IDs and uses atomic replacement. Users must NOT manually invent a name or rename a replay log to fit this format. Archive files may be incomplete if HA was not running or the source failed.

The recorded JSONL input lacks verified event and session IDs, so importing it as an authoritative session archive would require guessing; use it for a separate, clearly labeled replay fixture/import pipeline only.

## Completed on dev

1. Dependency-free persistent session archive prototype, explicit no-spoiler gate, session-ID matching and restart recovery.
2. Ten offline regression tests and a deterministic isolated coordinator candidate builder pinned to an audited repo snapshot.
3. Read-only local preflight script `scripts/motogp-backend-preflight.py`: reports installed Python version, integration file blob hashes, schema validity and any JSONL capture files. It never edits files and does not deploy or restart HA.
4. GitHub Actions `backend-session-archive-check.yml` compiles code, runs regression and preflight smoke tests, checks builder output and hash pins, and publishes the **uninstalled** candidate as an expiring review artifact.

## Must pass before release/install

1. Run preflight on the *actual* target HA host, review exact installed coordinator and companion module hashes and Python version; never assume the repo baseline matches HACS's installed code.
2. Rebase and inspect the archive hook against those installed hashes, including other upstream changes; verify `tv_delay_ready` semantics, exact event/category/session identifiers, and complete-lap extraction in real coordinator results. A coordinator-only patch from a mismatched baseline is prohibited.
3. Exercise integration lifecycle (setup, refresh, unload, restart), file permissions, multiple config entries, disk failure handling, red flag, finished/next-session transitions and real TV-delay/no-spoiler behavior. Archive writing must not block the HA event loop.
4. Expose archived rider laps to Next only through a deliberately designed safe read path. Do not treat a local JSON file or the archive prototype's `read()` guard as a complete authenticated frontend API.
5. Package a versioned full integration release with a fail-closed installer, checksum verification, an actual rollback and no changes to the existing `/local/ha-motogp-next.js` resource or original HACS cards. Document the single command and HA reload/restart requirements.
6. Separate replay preview importing and per-class Moto2/Moto3 championship standings from the archive release. Do not claim those features have shipped without their own working backend and UI tests.

## Preflight (read-only)

The script is in this repository at `scripts/motogp-backend-preflight.py`. Run it on the HA host from wherever the script was downloaded, for example:

```bash
python3 /config/config/motogp-backend-preflight.py
```

The script defaults to `/config` as the Home Assistant configuration root. It reports `BASELINE_MATCH_REVIEW_STILL_REQUIRED` or `INSTALLED_CODE_MUST_BE_REBASED`. Neither verdict authorizes installation on its own. Treat all host-derived output as private until reviewed.
