# Existing MotoGP dashboard: missing weekend schedule — investigation 2026-09-18

## User requirement and scope

**Develop the existing dashboard, not a replacement Card-test frontend.** The schedule should show today's sessions automatically, gray completed sessions, and keep the remaining weekend under day expanders. Do not overwrite the working dashboard, live Python, or active package until actual HA state confirms the change.

## Confirmed source-level fault: an arbitrary finished session hides the weekend

The exact active package captured from HA is tracked at [`config/packages/motogp_dashboard_mode.yaml`](../config/packages/motogp_dashboard_mode.yaml). Its `binary_sensor.motogp_weekend_view_available` tests the *currently observed live session* status (`Finished` / `F` / `C`) before allowing the weekend view. When an ordinary FP/Q/Practice session finishes, it becomes false unless `input_datetime.motogp_postrace_until` is still in the future. That helper is ordinarily set only on a completed MotoGP `RAC`, not each practice. Therefore the package can hide the weekend prematurely after any session. The existing `motogp_schema_auto_dag_v10.yaml` has top-level `visibility` requiring `binary_sensor.motogp_weekend_view == on`; a false gate removes **all six schedule cards**. This is a verified code logic defect, but current HA entity values are not captured in this turn, so its role in the screenshot is not yet proven.

A **complete replacement candidate** preserving the helper/automation identifiers is in [`proposals/motogp_dashboard_mode_weekend_gate_candidate.yaml`](../proposals/motogp_dashboard_mode_weekend_gate_candidate.yaml). It derives visibility from race-week/event dates and the existing postrace-until helper, instead of using arbitrary session status. It is only a proposal in GitHub: **do not copy alongside the existing HA package (duplicate helpers)**. If approved and actual live state matches, replace the single existing `/config/packages/motogp_dashboard_mode.yaml`, validate HA config, and test after reload/restart. Simulated Jinja cases cover Friday after FP, Saturday after Q, Sunday after RAC, Monday midnight, future event and explicit postrace-until. This does not repair incorrect backend event selection or guarantee the postrace automation triggers if `next_event` changes early.

Past sessions get `done-tile` and gray styles. A single **header-only** date helper incorrectly renders `YYYY-M-D`, but the day-panel helpers are correct. It is a consistency fix, **not** the explanation for missing day expansion.
